# Contributing to harness.talk

Thank you. This project exists so that agents and people have a place they can always return to for the Word, exact and verifiable. Contributions are welcome from people and from agents alike. The practical guide (build gates, the single tool manifest, how to propose a source) is on the Community page of the site; this file covers the legal terms so that nothing about them is implied.

See `packages/harness/LICENSE` and `packages/harness/LICENSE.GPL`. Any program under any licence may link to them.

Why two licences: the AGPL keeps the service open even when someone runs a modified copy for others over a network; the LGPL keeps the clients usable by every agent regardless of how that agent is licensed.

## The four freedoms

Both licences are on the Free Software Foundation's list of free software licences and grant the four freedoms as the [FSFE states them](https://fsfe.org/freesoftware/freesoftware.en.html):

| Freedom | Granted by |
| --- | --- |
| **Use** — any purpose, no expiry, no territory | AGPL §2, §9; LGPL §1 |
| **Study** — source available to anyone, no NDA | AGPL §1, §6, §13 (network use) |
| **Share** — copy and redistribute at no cost | AGPL §4, §6, §10 (no licence fee); LGPL §4 |
| **Improve** — modify and publish the modifications | AGPL §5, §13; LGPL §2 |

## Forking

A fork is a free act and needs no permission. Anyone may take this code, change it, and publish the result under their own name and copyright. The licence follows the code: AGPL §5(c) and §10 require a fork to stay under the same terms with no added restrictions, and §13 requires a fork that serves others over a network to offer its source. A fork cannot make this software proprietary, and nothing in this file limits the right to fork.

## Copyright assignment (contributions to this repository)

Assignment applies only to changes you submit *here*. If you would rather keep your copyright, fork instead — that path is always open.

By submitting a contribution (a pull request, a patch, a suggested edit that is merged) you:

1. **Assign** to the project maintainer the copyright in your contribution, to the fullest extent permitted by law, and where assignment is not permitted grant an exclusive, perpetual, irrevocable, worldwide, royalty-free licence to use, modify, distribute, sublicense, and relicense it.
2. **Certify** that the contribution is your own original work or that you have the right to assign it, that it contains no third-party code under terms incompatible with the licences above, and that it does not knowingly alter Scripture text without a cited printed edition.
3. **Receive back**, immediately and automatically, the same freedoms as everyone else: the maintainer licenses every merged contribution to the public under the AGPL-3.0-or-later (service) or LGPL-3.0-or-later (clients) as applicable.

Assignment means there is one copyright holder who can enforce the licences, correct mistakes in them, and carry this code into future work. It does not mean the work can be taken away from you or from anyone: the free licences above are irrevocable for every version already published.

If you cannot assign copyright (for example, your employer owns your work), open an issue before submitting so the terms can be handled explicitly.

## Attribution

Contributors are credited in the commit history, which is permanent. If you would like to be listed by name or handle elsewhere, say so in the pull request.

## Conduct

Bring citations by ref so every claim about the text can be checked at its address. Disagree plainly and kindly. Never fabricate a verse, a note, a reading, or a source.
